# 《三分天下·再起》地图编辑器（Map Forge）方案 v1

> 目标：做一个**魔兽争霸 3 世界编辑器级别**的 RTS 地图工具——用少量基础设定自动生成地图，生成后可在 3D 场景里自由修改，改完直接给游戏用。
> 代码基线：`C:\Users\shy\桌面\Godot`（Godot 4.7.2 mono / GDScript / Forward+）
> 日期：2026-10-23

---

## 0. 结论先行

**三句话判断：**

1. **不要照抄魔兽 3 的瓦片地形。** 你的游戏已经是"连续高度场 + 混合贴图 + 3D 相机"，瓦片（Tile/Clliff Level）那套会把你现有 `Terrain.gd` 全部推翻。正确做法是：**保持高度场，把 WC3 的"笔刷 + 图层 + 对象层 + 区域 + 触发器"的交互模式搬过来。**
2. **编辑器的技术形态选"独立工具场景"，不选 Godot EditorPlugin。** 因为你的 `Building.tscn / Unit.tscn` 依赖 `DataLoader / GameManager` 这些 autoload 才能 `_ready()`，只有在**运行时场景**里才能做到"放下去就是真的建筑、真的单位"，所见即所得。EditorPlugin 里跑不动这套逻辑，还要自己重写 viewport 绘制和 gizmo。
3. **"自动生成"的真正门槛不是噪声，是公平性。** 能当正式对战图用，必须做**对称化（点对称/旋转对称）+ 起点评分选址 + 资源均衡铺设 + 连通性校验**。这四项做不出来，生成的地图只能当草稿。

**当前代码已经有的地基（可以直接用，不用重写）：**
- `Terrain.gd`：高度图（256² RF）+ 群系图（256² RGBA）+ 种子化参数（`MapParams` 28 个字段）
- `MapSaveManager.gd`：地图存 `user://maps/<name>/params.json`
- `MapGenerator.gd`：11 个滑块的调参面板 + 2D 俯视预览（**只有面板，没有 3D 编辑**）
- `GridManager / Pathfinder`：84/120/168 三档网格，建筑占位、水域不可通行、A*
- 数据驱动资产：32 建筑 / 36 兵种 / 资源点 / 村庄 / 野马，全部 JSON 定义

**当前最大的缺口：** 地图内容（基地位置、树、矿、村庄、野马）**全是 `Main.gd` 里硬编码的**（`0.12*N`、`0.83*N` 这种比例写死 + 固定随机种子）。所以现在"地图"其实只有地形，没有"地图内容"这一层。**地图编辑器的第一件事，就是把这一层抽出来变成数据。**

## 1. 现状核查（逐项对照代码，含必须先修的坑）

| # | 事项 | 代码事实 | 对编辑器的影响 |
|---|---|---|---|
| 1 | 地形数据 | `Terrain.heightmap_img` (FORMAT_RF, 256²)、`biome_img` (RGBA8, 256²) | ✅ 可直接改造成可编辑图层 |
| 2 | 地形网格 | `PlaneMesh.subdivide = clampi(int(world_size), 64, 400)` | ⚠️ 网格细分 168~336，而高度图 256 → **笔刷改一个像素可能落在两个顶点之间，视觉上看不出变化**。必须先改成按高度图分辨率建 ArrayMesh |
| 3 | 高度单位 | 生成时 h ∈ [-0.9, 0.64]，`get_height` 返回 `h * max_height` | ✅ 逻辑自洽；但见第 4 条 |
| 4 | **水面/最高高度双份来源（Bug）** | `Main._create_terrain_material()` 把 `Terrain.WATER_LEVEL`（常量 -5）和 `Terrain.MAX_HEIGHT`（常量 16）传给 shader；而 `get_height()` 用的是 `params.max_height / params.water_level` | ⚠️ 地图生成器里的"水面高度"滑块**只改了水，没改水的显示**，改完地形和视觉会错位。编辑器必须统一为"只认 params" |
| 5 | 地形贴图 | `_load_terrain_tex()` 里加载 PNG 的代码**被注释掉了**，永远返回纯色 2×2 | ⚠️ **现在游戏里的地表全是纯色块**，AI 生成的 7 张地形图完全没被使用。贴图笔刷要在这一步先恢复 |
| 6 | 群系图分辨率耦合 | `Terrain.generate()` 第二遍用 `heightmap_img.get_pixel(px, py)` 直接索引，隐含 `biome_size == heightmap_size` | ⚠️ 两者不一致就静默出错。编辑器要显式解耦 |
| 7 | 地图内容 | `_spawn_initial_forces / _spawn_decorations / _spawn_resource_nodes / _spawn_villages / _spawn_wild_horses` 全部硬编码比例坐标 + 固定 rng seed（424242/12345/99999/77777） | 🔴 **这是要拆的核心**。编辑器产出 = 这些列表的数据化版本 |
| 8 | 预设地图 | `config/maps.json` 存了 5 张图的城市名+坐标，但 `Main.gd` **只用 `size` 字段**，`cities` 全部被忽略 | 🔴 说明"地图内容"这一层从来没接上。编辑器正好补这个洞 |
| 9 | 存图 | `MapSave.save_current_map()` 只存 `params.json` + `biome.png`（高度图没存） | 🔴 缺高度图 → 手改过的地形存不下来 |
| 10 | 编辑器入口 | `scenes/MapGenerator.tscn` 存在，但**主菜单里没有入口**，只能手动打开场景 | 需要接到主菜单 |
| 11 | 网格/世界尺寸 | `world_size = n * cell_size`（n=84/120/168，cell=2 → 168/240/336） | ✅ 这条契约必须守住，编辑器所有坐标都基于它 |
| 12 | **单位/建筑贴图全链路断开（Bug）** | `DataLoader.get_sprite_texture()` 第 94 行**硬编码 `return null`**，后面 30 行加载逻辑全是死代码 | 🔴 **现在游戏里没有任何一张精灵贴图在生效**。所有单位/建筑都走 `BoxMesh`/程序化 mesh fallback。见第 12 节 |
| 13 | 2.5D 渲染（已具备） | `Unit.gd:155` `_sprite.billboard = BILLBOARD_ENABLED`（始终朝向相机）；`Building.gd:197` `BILLBOARD_DISABLED`（固定朝向）；`Sprite3D.shadow_cast = ON` 投真阴影 | ✅ **项目本身就是 2.5D**，不是「将来要不要 2.5D」的问题 |

## 2. 目标定义：什么叫"像魔兽 3 一样强大"

魔兽 3 世界编辑器的模块（官方 F3~F8）：

| WC3 模块 | 作用 | 本项目对应 | 优先级 |
|---|---|---|---|
| Terrain Editor (F3) | 改地形、放单位/装饰/区域/相机 | **地形笔刷层 + 对象层 + 区域层** | P0/P1 |
| Trigger Editor (F4) | GUI 事件-条件-动作，能做完整战役 | **JSON 触发器 + 运行时解释器** | P3 |
| Object Editor (F7) | 改单位/技能/建筑数值，造自定义单位 | **复用 `config/*.json` + 地图级 override** | P2 |
| Sound Editor (F6) | 音效音乐管理 | 地图级音效表 | P4 |
| AI Editor (F8) | 自定义电脑行为 | 挂 `AIController` 参数档 | P3 |
| Object / Import Manager | 管理地图内所有对象、导入素材 | 对象管理器 + 图层面板 | P4 |
| Region / Camera | 触发器用的区域、过场相机 | 区域层 + 相机标记 | P3 |
| Map Properties | 玩家/势力/天气/雾/胜利条件 | 地图属性面板 | P1 |
| **（你的新增需求）自动生成** | —— | **生成向导 Generator Wizard** | P1 |

**明确不做（至少 v1 不做）：**
- ❌ 瓦片/崖级地形（与连续高度场冲突）
- ❌ JASS 式的脚本语言（用 JSON 触发器 + 可选 GDScript 逃生口）
- ❌ 自定义单位模型导入（你走 GLTF 管线，不在地图编辑器里做）

## 3. 总体架构

三层，边界清晰：

```
┌─────────────────────────────────────────────────────────┐
│  ① 数据层  MapDoc（唯一事实源）                            │
│     height.exr / biome.png / map.json                     │
│     地形参数 + 对象列表 + 区域 + 玩家 + 触发器 + 属性        │
└───────────────┬─────────────────────────┬───────────────┘
                │ 读写                     │ 读取
┌───────────────▼──────────────┐  ┌───────▼────────────────┐
│ ② 编辑器 Timeline/MapEditor   │  │ ③ 运行时 MapRuntime     │
│  3D 场景 + 笔刷 + 调色板       │  │  Main.tscn 加载后       │
│  + 生成向导 + 校验器 + 撤销栈   │  │  按 doc 铺地形/摆对象   │
│  → 产出 MapDoc                │  │  + TriggerRuntime 监听  │
└───────────────────────────────┘  └────────────────────────┘
```

**关键约束：编辑器与游戏共用同一套 `Terrain` / `GridManager` / `Building.tscn` / `DataLoader`。**
编辑器不是另一套渲染，就是把游戏的渲染拿来当画布。这样"编辑器里看到的 = 游戏里跑出来的"，不需要第二套预览代码。

## 4. 地图文件格式（MapDoc）

**开发期用目录，发布期打包成 `.sgmap`（就是 zip，Godot 自带 `ZIPPacker/ZIPReader`）。**

```

├── map.json          # 全部元数据 + 对象列表（人可读，可 diff）
├── height.exr        # float32 高度图（无损；EXR 还能量化查看）
├── height_preview.png# 8bit 灰度预览（给缩略图/调试用）
├── biome.png         # RGBA8 群系权重：R=森林 G=土地 B=石板 A=保留
```

**视口必须有的四件叠加物（缺一个都会让操作变笨）：**
1. **网格叠加**（`grid.map_size` 线框，1 格 = 2m，拉远自动隐藏）
2. **笔刷圈**（贴地投影的圆环，不是屏幕空间圆）
3. **对象 footprint**（拖建筑时显示 `buildings.json` 的 `size`，非法位置染红）
4. **等高线/坡度着色**（开关，编辑地形时用）

## 6. 六大工具体系

### 6.1 地形笔刷层（P0 核心）

| 笔刷 | 行为 | 实现要点 |
|---|---|---|
| 抬升 / 下压 | `h += strength * w * dt` | w = 平滑衰减 `smoothstep(1 - r/R)` |
| 平滑 | `h = lerp(h, 邻域均值, w * strength)` | 3×3 或 5×5 采样 |
| 平台（Flatten） | `h = lerp(h, target_h, w * strength)` | target_h 取起笔点高度 |
| 陡坡（Cliff） | 在半径内硬插值到目标高度，边缘宽度可调 | 近似 WC3 崖级，视觉即陡壁 |
| 噪声 | 叠加一层 `FastNoiseLite` 到局部 | 做山脊/碎石细节 |
| 直线/道路 | 起点→终点，沿线半径刷 | 河流、官道 |
| 填充 | flood fill 同高度区域到目标高度 | 整片台地 |

**坐标拾取方案（很关键，别用平面射线）：**
```gdscript
# 地形 CollisionShape3D 用 HeightMapShape3D，和高度图 1:1 对应
var shape := HeightMapShape3D.new()
shape.map_width = hms
shape.map_depth = hms
shape.update_map_data_from_image(height_img, -0.9 * max_h, 0.64 * max_h)
# 拾取时直接 PhysicsDirectSpaceState3D.intersect_ray()
```
这比"射线和 y=0 平面求交"准确得多，笔刷才能贴着山坡走。改完高度要同步 `update_map_data_from_image()`。

**性能策略（1024² 也扛得住）：**
- 高度图固定 **512×512**（精度 0.065m/级，够用；1024 只在"超大地图"选配）
- 每帧只重算笔刷影响圈内像素，然后 `ImageTexture.update(img)` 整图上传（512² RF = 1MB/帧，桌面无压力）
- 地形网格改成 **ArrayMesh，顶点数 = 高度图分辨率**（512² = 26 万顶点）。这样"视觉地形"和 `get_height()` 完全一致，笔刷改一像素就看得见

### 6.2 贴图层（P2）

现有 `biome` 只有 3 通道（森林/土地/石板），shader 里 草/岩/沙/雪 靠高度坡度自动推导。要做"贴图笔刷"就扩成两张：
- `biome.png`：草 / 土 / 石 / 林（4 通道）
- `splat.png`：沙 / 雪 / 岩 / 道路（4 通道）

shader 里从 `mix` 三层变 `mix` 七层。⚠️ **前提是先修第 1 节第 5 条**（把被注释掉的贴图加载恢复），否则画了也看不出来。

### 6.3 对象放置层（P0 核心）

- 调色板数据源：`DataLoader` 全部建筑/单位 + 资源/村庄/野马
- 放置流程：`hover → ghost(半透明真实场景) → footprint 合法性染色 → 左键落位 → 写 objects[] → 建 grid 占位`
- **ghost 逻辑直接抽 `Main.start_build_mode()` 那套**成 `PlacementGhost.gd`，游戏内建造和编辑器共用
- 旋转：建筑 90° 步进（footprint 的 x/y 互换），单位任意角
- 选择/拖动/删除/框选/复制粘贴（Ctrl+C/V）/Alt 拖动复制
- 编辑器模式标志：`GameManager.editor_mode = true` → 实体跳过 `_process` 的资源结算、AI、建造进度。**这一条不做，放 20 个建筑游戏就自己跑起来了**

### 6.4 区域层（P3）

矩形 / 圆 / 多边形三种，带 `tags`（`no_build` / `spawn` / `fire` / `ambush`）。
用途：禁建区、触发器范围、刷兵区、镜头引导。编辑器里半透明彩色面片 + 顶点拖拽。

### 6.5 玩家层（P1）

每槽位：势力（wei/shu/wu/中立）、起点、颜色、初始资源、是否玩家控制。
放置"起点标记"时自动吸附到最近的可建空地（复用 `_find_placeable()`）。

### 6.6 触发器层（P3，WC3 的灵魂）

JSON 三段式：`events / conditions / actions`，运行时由 `TriggerRuntime.gd` 解释。

首批覆盖（够写完整战役）：
- **事件 12 个**：时间到、单位进入区域、单位死亡、建筑被毁、资源达到、玩家选中、技能释放、夜晚开始、变量比较、计时器周期、单位被攻击、地图初始化
- **条件 10 个**：阵营比较、单位类型、区域包含、资源量、存活数、变量、概率
- **动作 20 个**：显示对话、播放音效、创建单位、删除单位、移动单位、加资源、改阵营、镜头平移/锁定、任务目标增删、胜利/失败、开启/关闭触发器、设置天气、显示倒计时、开门…

逃生口：`{ "type": "gdscript", "path": "res://maps/custom/xx.gd" }`（仅本地图允许）。

## 7. 自动生成算法（"基础设定就能出图"）

### 7.1 向导流程

```
① 选模板  →  ② 填参数  →  ③ 生成预览  →  ④ 重掷/微调  →  ⑤ 进编辑器手改
```

**模板库（P1 先做 5 套）：**

| 模板 | 特征 | 适合 |
|---|---|---|
| 全面战争 | 点对称，2 个对角基地，中间资源富集 | 1v1 标准 |
| 峡谷关隘 | 一条主通道 + 两侧山地，隘口有中立箭塔点 | 3v3 拉锯 |

### 7.2 对称化（公平性的根）

```
2 人 → 中心点对称：   h'(p) = h(2c - p)
4 人 → 四重旋转对称
n 人 → 环向等角扇区，扇区内旋转复制（radial symmetry）
```
实现方式：对高度图按对称群做"取最大值合成"（`h = max(h(p), h(g·p))` for g in group）。这样任何地形特征都会在对方半场出现一份镜像，起点到资源的相对关系天然对等。

**这是生成图能不能当正式图用的分水岭。不做对称 = 永远有一方吃亏。**

### 7.3 起点选址（评分法）

在陆地上撒候选点（间距 8 格），对每个点算分：

```
score =  w1 * 两两最小距离（越大越好）
       + w2 * 周围 15×15 可建面积占比
       + w3 * 半径 12 格内 wood/stone/food 总量
       - w4 * |到地图中心距离 - 平均距离|
       - w5 * 坡度均值（太陡不适合建家）
```
贪心选第一个点，后续点要求与已选点距离 > 阈值，取分数最高组合。n ≤ 8 时直接枚举组合也很快。

### 7.4 资源/内容铺设

- 每方基地半径 10 格内：1 片树林 + 1 处石矿（保证开局不断粮）
- 中立矿：按对称位置铺设，`is_mine=true`、`amount=99999`
- 中立村庄：对称轴两侧成对出现（否则又是公平性问题）
- 树木/岩石：按 biome 权重图撒点（森林通道多树，石板地少树），**用种子驱动，保证同图可复现**
- 野怪/中立营寨：对称点各一

### 7.5 地图校验器（保存前必跑）

| 检查 | 级别 | 说明 |
|---|---|---|
| 起点在陆地且 15×15 可建 | 错误 | 否则开局就废 |
| 起点两两距离 ≥ 阈值 | 错误 | 挤在一起没法打 |
| 每方最近木材/石料 A* 可达 | 错误 | 有资源但走不到 |
| 建筑越界/重叠 | 错误 | footprint 冲突 |
| 陆地连通性 | 警告 | 被水隔断（水战图需显式豁免） |
| 死角资源/不可达区域 | 警告 | |
| 对称偏差（若非自由设计） | 警告 | 生成图用 |

输出到状态栏：`0 错误 2 警告`，点开可定位跳转。

## 10. 风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| **高度场做不出 WC3 的离散崖级** | 连续场只有坡度，没有"一层层台阶" | 用"陡坡笔刷 + 平台笔刷"近似；真崖级（cliff mesh）留 P4，绝大多数 RTS 地图不需要 |
| **地形分辨率 vs 网格分辨率** | 高度图 512、网格 168 → 1 格 = 3 像素 | 笔刷按像素走、放置按格吸附；两者互不干扰，但地形网格必须 ≥ 高度图分辨率 |
| **编辑器/游戏共用 autoload 全局态** | `Terrain.params` 是全局单例，编辑器切图会改全局 | 所有切场景走"存文件→重载场景"，不靠内存态传递 |
| **触发器范围失控** | 完整 TESH 是个无底洞 | 硬性限定：只做 12/10/20 的首批清单，超出的一律走 GDScript 逃生口 |
| **性能** | 512² 地形 + 数百对象 + 每帧笔刷上传 | 笔刷只在拖动时更新；对象用 MultiMesh 留给 P2 优化；编辑器不做 AI/寻路 tick |
| **资产未透明/AI 图未接** | 第 1 节第 5 条：地形贴图目前是纯色 | P0 顺手修掉，否则贴图笔刷没有意义 |

## 12. 2.5D 专项（贴图优先路线）

> 结论：**本方案与投影方式完全解耦，2.5D 是原生支持而不是妥协。**
> 但 2.5D 有 4 条它自己的硬规矩，不遵守编辑器做得再好也白费。

### 12.1 为什么编辑器天然支持 2.5D

编辑器存的是 `{ kind, id, grid, rot }`，**它不知道也不关心这个 id 最后长什么样**。
`Unit.gd` / `Building.gd` 各自决定怎么渲染：

| 模式 | 单位渲染 | 建筑渲染 | 换起来要改 |
|---|---|---|---|
| **当前 2.5D 贴图** | `Sprite3D` + `BILLBOARD_ENABLED` + alpha | `Sprite3D` + `BILLBOARD_DISABLED` + `pixel_size` | 改 `asset_map.json` 换图 |
| 将来 3D GLTF | `MeshInstance3D` + `AnimationTree` | 同 | 只改这两个 `_create_sprite()` 内部 |

**同一份 `map.json` 在两种模式下都能跑**，因为地图只记录逻辑位置。所以「前期贴图、后期换 3D」不需要重做地图。✅

### 12.2 必须先修的两处断线（P0，不做则贴图无效）

**① 精灵贴图：`scripts/data/DataLoader.gd:94`**

```gdscript
func get_sprite_texture(category: String, entity_id: String) -> Texture2D:
	# V2 workaround: headless 模式 .ctex 缓存可能不存在
	# 在 Godot Editor GUI 里打开一次项目，它会自动导入所有资源
	# 导入完后注释掉下面这行即可恢复 sprite 显示
	return null          # ← 这一行让 asset_map.json 里 60 条映射全部失效
```

`config/asset_map.json` 里其实**已经写好了**：21 单位 + 4 武将 + 27 建筑 + 3 资源点 + 1 村庄 + 4 野马，全部映射到 `assets/sprites/*.png`（70 张图已在目录里）。断的只是这一行。

处理方式（比删掉 `return null` 更稳）：
```gdscript
# 改为：缓存优先 + 失败静默降级，而不是一刀切禁掉
var _tex_cache: Dictionary = {}
func get_sprite_texture(category: String, entity_id: String) -> Texture2D:
	var key := category + "/" + entity_id
	if _tex_cache.has(key):
		return _tex_cache[key]
	var tex: Texture2D = null
	var adef := get_asset_def(category, entity_id)
	var fn: String = str(adef.get("sprite", ""))
	if fn != "":
		for p in ["res://assets/sprites/%s" % fn, "res://assets/sprites/%s/%s" % [category, fn]]:
			if ResourceLoader.exists(p):
				tex = load(p) as Texture2D
				if tex != null: break
	_tex_cache[key] = tex
	return tex   # null 时调用方已有 fallback，不会崩
```

**② 地形贴图：`Main._load_terrain_tex()` 里 `load()` 被注释掉**（第 1 节第 5 条），永远返回 2×2 纯色。`assets/terrain/` 下 7 张真图（grass/dirt/sand/rock/snow/stone/forest）**一张都没生效**。

这两处一修，游戏会立刻从「纯色方块 RTS」变成「有素材的 RTS」——这比重写十遍编辑器都更有效果。

### 12.3 2.5D 的四条硬规矩

**规矩 1：相机必须锁死一个角度（最重要）**

`CameraController.gd` 现在 `_rotation_y` 是**无限制 360° 旋转**（Q/E + 右键拖拽）。而建筑是 `BILLBOARD_DISABLED` 的**单方向平面图**——转到背面，你看到的就是一张纸的侧棱。

三条出路，选一条：

| 方案 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A. 锁定俯角 + 固定朝向**（推荐） | `_rotation_y` 只允许 4 档：0/90/180/270，且 45° 俯角固定 | 素材要么只做 1 个朝向（只玩 1 档），要么做 4 朝向 | 傲世三国/帝国时代老派 2.5D |
| B. 建筑也开 billboard | `BILLBOARD_ENABLED` | 建筑会"永远正对镜头"，翻转让房子像贴纸，失去体积感 | 快出效果，不耐看 |
| C. 换 3D 模型 | GLTF + 卡通着色 | 美术成本 | 最终形态 |

**建议：现在走 A（相机锁 0° 单档 + 素材只做 1 朝向），编辑器里先当画布用；等 3D 模型到位再解锁旋转。** 编辑器相机必须和游戏相机同一套参数，否则「编辑器里好看、进游戏歪了」。

**规矩 2：所有精灵图必须同一个拍摄角度**

`asset_map.json` 现在混着从傲世三国素材里扒的 BMP，**每张的视角角度不统一**。判断标准：**画面里能看到建筑屋顶的面，且侧面只看到 1 个方向**（约 30~45° 俯角、正面微侧）。角度不统一的图放在一起，2.5D 会立刻"垮掉"——这是 2.5D 最贵的隐性成本。

编辑器对策：**素材导入时逐张校验**（第 12.4 节的 AssetImporter 做人工确认位），P2 加"角度参考网格"叠加层辅助对齐。

**规矩 3：画布底边 = 地面线（脚底锚点统一）**

`asset_map.json` 里每条都有 `offset_y`（0.5~1.5 不等），说明**每张图的脚底位置都不一样**，靠手调补偿。这在编辑器里会炸：用笔刷刷 200 棵树，每棵都要单独调 offset。

统一规范（必须定死，不然以后所有素材都要返工）：
- 画布尺寸统一（比如单位 128×192、建筑 256×256）
- **精灵的"接地线"必须在画布最底部往下留固定 2px 透明**，即内容底边对齐 `H-2`
- 定死之后 **`offset_y` 全部归零**，高度由 `scale` 单独控制
- 编辑器加一个「锚点预览」：选中素材时画出接地线和 footprint 框

> 这正是之前精灵表方案踩过的「脚底漂移」坑。**单图 2.5D 也一样会踩，只是变成"每张图偏移不一致"。**

**规矩 4：透明精灵的排序（Z-fighting）**

多个 alpha 精灵前后重叠时，Godot 的透明排序会闪（尤其树挡住单位）。对策：
- 树/装饰用 `Sprite3D` + `alpha_cut = ALPHA_CUT_DISCARD`（硬边裁剪，可进不透明队列，排序稳定）
- 单位保持 `TRANSPARENCY_ALPHA`（软边好看），但**关掉它的 `depth_draw`**
- 编辑器"遮挡预览"开关：模拟游戏里的真实遮挡顺序

### 12.4 「只往里贴图」需要的素材导入流程（方案原缺，现补）

现状：往 `assets/sprites/` 丢一张 PNG，**游戏里不会有任何变化**——必须手改 `asset_map.json` 加一条映射。编辑器要做到「贴图即用」，需要这个模块：

```
scripts/mapeditor/AssetImporter.gd
  ├─ import_png(src_path, category, entity_id)
  │    1. 校验尺寸/透明通道/接地线是否合规
  │    2. 拷到 assets/sprites/，按 <category>_<id>.png 规范命名
  │    3. 自动生成/更新 asset_map.json 条目（scale 按画布高度推算，offset_y = 0）
  │    4. 刷新 DataLoader 缓存
  └─ list_imported(category)  # 给调色板用
```

编辑器里的「调色板」因此变成两级：
1. **已注册素材**（asset_map 里有的）——直接放
2. **未注册图片**（`assets/sprites/` 里游离的 PNG）——调色板里灰显展示，点一下走导入向导

**这才是「前期只往里贴图」的正确形态**：拖一张图进窗口 → 指定它是建筑/单位/装饰 → 填尺寸 → 立刻能在编辑器里摆，进游戏就能看到。

### 12.5 地形贴图（你贴的第二类图）

`assets/terrain/` 那 7 张是**平铺纹理**（tiling texture），和精灵是两回事：
- 它们是 shader 里按群系权重混合的 4~7 层
- 要求：**可无缝平铺**（左右上下边缘对得上）、**无明显方向光**（否则平铺后出现网格状明暗）
- 现在的 `grass/dirt/sand/rock/snow/stone/forest` 需要在 Godot 里确认是否满足这两点，不满足的话贴图笔刷画出来会有可见接缝

**编辑器侧的对应功能**：P2 的"贴图笔刷"（splat 双图方案，第 6.2 节）。如果你想**前期就先做贴图编辑**，可以把它从 P2 提到 P1。

---


**这个编辑器的本质是——把 `Main.gd` 里那 300 行硬编码的地图内容，抽成一份 `map.json`；然后给它配一个能改高度图、能摆对象、能一键生成对称地图、能存能玩的 3D 前端。**

先做 P0（闭环），不要先做触发器。P0 跑通那天，你就已经拥有一个比现在强十倍的"地图生成器"了。
