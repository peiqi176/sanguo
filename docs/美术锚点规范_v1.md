# 美术锚点规范 v1（2.5D 统一锚点）

> 2026-10-23 定稿。这份文件是**唯一标准**：出图、改图、换图都按它来。
> 代码侧对应 `CameraController`（相机）与 `DataLoader.get_sprite_anchor_y()`（贴地）。

---

## 0. 为什么必须统一

以前的素材是不同时期、不同提示词拼出来的，视角、比例、接地位置各不相同。
贴地公式自动化之后，问题反而更刺眼：**角度不统一会"歪得很整齐"** ——
一群兵站在一起，有的像正面、有的像侧面、有的像俯视，怎么调都对不上。

统一锚点 = 四个量被钉死：**相机视角、画面比例、接地基线、光源方向**。

---

## 1. 相机视角（引擎侧，不可改）

| 项 | 值 | 代码位置 |
|---|---|---|
| 俯角 pitch | **45°** | `CameraController.pitch_lock_deg` |
| 偏航 yaw | **45°** | `CameraController.yaw_lock_deg` |
| 旋转 | **锁定**（yaw_lock_step = 360，只有一档） | `CameraController` |
| FOV | **32°**（长焦，接近正交，屏幕边缘不拉伸） | `CameraController.camera_fov` |
| 距离档位 | 18 m（看清一个兵）～ 110 m（看全战场） | `min_height` / `max_height` |

**为什么锁偏航**：建筑是 `BILLBOARD_DISABLED` 的单方向平面图，相机一转就看到"纸片侧棱"。
锁死 45° 后，所有建筑共用同一个观察方向，等距投影才成立。

**为什么 FOV 从 50 降到 32**：50° 广角会把屏幕边缘的纸片人横向拉宽，
近处胖、远处瘦，同一张图在不同位置看起来不一样 —— 这在大地图上非常明显。

## 2. 出图锚点（美术侧，逐条对照）

### 2.1 投影与朝向

- **单位**：等距视角，相机俯角 45°、偏航 0°（正面朝向观众，能看到一点头顶）
- **建筑**：等距投影，相机俯角 45°、偏航 45°（**同时看到正面与右侧面**）
- 单位站姿：双脚**并排**落地，不要一前一后（否则脚底线对不齐）
- 建筑构图：**地基贴齐内容底边**，不画台基以外的地面

### 2.2 光源

- 主光从**左上方 45°** 入射
- 右面、下沿为暗部；左肩、盔甲上缘、屋面左坡有明确高光
- 不画任何**落地投影、地面阴影、倒影**

### 2.3 画布与接地

| 类别 | 画布 | 内容高度 | 说明 |
|---|---|---|---|
| 单位 / 武将 | 256 × 256 | **200 px**（= 内容占 78%） | 脚底距画布底边 3 px |
| 建筑 | 512 × 512 | **400 px**（同样 78%） | 地基距画布底边 3 px |
| 装饰（树 / 石） | 256 × 256 | 按实际 | 树根贴底边 |

> **78% 这个比例不能再改**。引擎按画布高度换算世界尺寸，
> 内容占画布的比例就是"这张图和别人一样高吗"的唯一依据。
> 以前 70 张贴图的底边留白从 0% 到 22% 乱跑，正是"有的兵陷进地里、有的浮在半空"的根因。

### 2.4 背景

- 必须是**真正透明的 PNG alpha 通道**（不是白底、不是绿幕）
- 不要边框、不要文字、不要装饰性光效

### 2.5 风格锚点（固定在提示词尾部，越靠后权重越高）

> 2.5D 即时战略游戏素材，帝国时代4式干净半写实插画风格，三国时期中国古典军制。
> 轮廓边缘锐利干净，色块分明，不糊不虚；画面里只有这一个对象，不要任何文字。

## 3. 提示词结构（六段式）

```
① 身份锚点（每个实体独有，绝不雷同）
② 装备 / 服饰（三国朝代风，颜色克制，留给引擎染阵营色）
③ 姿态（标准站姿，朝向镜头）
④ 画布与接地（全身完整入画，脚底贴齐画面最底边）
⑤ 背景（完全透明 alpha，无地面 / 无投影 / 无边框）
⑥ 风格锚点（上一节那段，固定不变）
```

**①是唯一变量。** ②③④⑤⑥ 全项目逐字相同 —— 这才是"统一锚点"。
每个实体的 ① 写在 `tools/gen_unified_sprites.py` 的 `SUBJECT` 字典里，
改文案只改那一个字典，不许在提示词里临时拼接。

### 示例（刀兵）

```
刀兵，蜀汉墨绿战袍配皮甲，头戴铁盔，右手持环首直刀斜指地面，左臂挎一面小圆木盾。
2.5D 即时战略游戏素材，帝国时代4式干净半写实插画风格，三国时期中国古典军制。
单一角色全身完整入画，正面朝向观众，等距视角（相机俯角45度、偏航0度），
双脚并排站立、脚底贴齐画面最底边，头顶不碰画布上沿。
光源来自左上方45度，右侧与下方为暗部，左肩与盔甲上缘有明确高光。
背景必须是完全透明的 PNG alpha 通道；不要画地面、投影、阴影、倒影、边框。
轮廓边缘锐利干净，色块分明，不糊不虚；画面里只有这一个对象，不要任何文字与装饰。
```

## 4. 后处理流水线

`tools/gen_unified_sprites.py` 生成后统一做四步，**不允许手工修图**：

1. 抠底（绿幕兜底，正常应为原生 alpha）
2. 去溢色（绿边像素压回中性）
3. 裁到 alpha 包围盒 → 等比缩放到统一内容高度
4. 脚底对齐画布底边、水平居中

这样出来的图，**贴地公式不需要任何人工偏移**，`offset_y` 全部保持 0。

## 5. 引擎侧换算（改比例时才看）

```
世界高度 = 画布高(px) × pixel_size × scale
pixel_size = ref_h × 0.01 / 画布高(px)
⇒ 世界高度 = ref_h × 0.01 × scale
```

| 类别 | ref_h | 实际 scale | 换算后画布世界高度 |
|---|---|---|---|
| units | 280 | **0.85** | 2.38 m（内容 78% → 兵高 1.86 m） |
| buildings | 340 | **2.60** | 8.84 m（内容 78% → 建筑高 6.9 m） |
| generals | 280 | **0.50** | 1.40 m（内容 ~100% → 武将 1.40 m，比兵略矮但服装更醒目） |

> ⚠ generals 那一行是 2026-10-24 实测后改的：立绘是 1024×1024、内容几乎占满画布，
> 原来 scale=1.7 会让刘备有 **4.7 米高**，站在兵群旁边像巨人。
> 统一到 0.50 后和其他单位在一个量级上。
> 兵 1.86 m、官府 6.9 m，比例约 1 : 3.7，与"两层重檐大堂"的实际观感一致。
> 换整套新素材时，`config/asset_map.json` 的 `scale` 要按上表**统一重写**，
> 不再逐个手调 —— 素材已经统一了，再逐个调就是把不统一又加回去。
> 这件事有脚本：`python tools/swap_v2_assets.py --write`
> （自动备份旧图到 `assets/sprites_backup_pre_v2/`、改 asset_map、之后跑一次 `--import`）。

## 6. 检查清单（每次出新图都过一遍）

- [ ] 透明底，四角 alpha = 0
- [ ] 内容高度 = 200（单位）/ 400（建筑），误差 ≤ 4 px
- [ ] 内容底边距画布底边 3 px
- [ ] 能看到左上方高光、右下方暗部
- [ ] 建筑能看到正面 + 右侧面（不是纯正面）
- [ ] 没有落地阴影、地面、边框、文字
- [ ] 与之同类素材并排看，高度一致、视角一致、光向一致

## 7. 投影匹配：为什么立绘必须画成「等距俯视 3/4 视角」

游戏相机是**俯角 45°、偏航 45° 的透视相机**，建筑立绘是一张贴在平面上的纸。
两者必须是对同一套投影的两次表达，否则就会出现"台基翘成斜板"。

**引擎侧的做法**（`Building._create_full_appearance()`）：
把纸面绕自身 X 轴后倒 `90° - 45° = 45°`，让它**垂直于相机视线**。
这样：
- 立绘 1:1 还原，不被透视压扁（否则高度只剩 0.707 倍，屋身发胖）；
- 立绘里画的"地面台基"在屏幕上正好是一个水平面，和 3D 地形严丝合缝。

**因此出图时的硬要求**：

| 项 | 要求 | 理由 |
|---|---|---|
| 视角 | 俯角 30°~35°、斜 45° 的 3/4 视角 | 与相机 45° 俯视是同一族投影，倾斜后不变形 |
| 底面 | **允许**画一块水平台基/台阶 | 倾斜后它是水平的，正好压住地形起伏的接缝 |
| 投影 | **绝对不要**画落在地上的阴影 | 引擎会投真实阴影，画了就有两套，方向一定对不上 |
| 高光 | 左上受光、右下背光 | 主光在 `SUN_EULER_DEG = (-55°, 45°, 0)` |
| 底边 | 台基前沿落在画布底部 3px | 贴地锚点取的是 alpha 包围盒底边 |

> 单位是另一套：`Sprite3D.billboard = BILLBOARD_ENABLED`（全向），平面本来就垂直于视线，
> 所以单位立绘**不需要**手动倾斜，也不该画台基（会跟着倒）。
